# 개발 로드맵

현재 구현된 API MVP에서 도메인 특화 LLM과 추론 시스템 실험으로 확장하기 위한 계획입니다. 아래 항목은 완료된 성과나 보장된 비용 절감 효과가 아닙니다.

## 1. API MVP 안정화

- API 잔액 충전 후 실제 채점 성공까지 전체 흐름 검증
- 구조화된 출력 실패·거부 응답·타임아웃·지시 주입 평가
- 사용자별 요청 제한과 일일 비용 상한 설계
- 요청 단위 토큰 사용량, 처리 시간, 오류율 계측
- 답변 본문을 로그에 남기지 않는 운영 방침 마련

완료 기준: 정상 요청과 실패 요청을 재현할 수 있고, 요청당 비용과 지연 시간의 기준선을 측정할 수 있을 것.

## 2. 데이터와 독립 평가셋 구축

- 서비스 분석 동의와 구분된 학습용 데이터 수집 동의
- 개인정보 제거, 보존 기간, 삭제 요청 처리 설계
- 루브릭 버전·문항·답변·초안 점수·검토 이력 관리
- LLM 초안 라벨 일부를 독립적으로 검토하고 평가자 간 일치도를 측정
- 자기신고 MBTI와 결과 공감도는 별도 보조 지표로 보관
- 사용자 및 유사 답변 기준으로 학습/검증/테스트를 분리

완료 기준: 모델이 생성한 라벨을 그대로 정답 삼지 않는 독립 테스트셋 확보. 현재는 데이터 수집 기능이 없으며 실제 사용자 답변을 저장하지 않음.

## 3. 오픈소스 LLM 파인튜닝

- 한국어 이해, 라이선스, 메모리 요구량을 확인한 소형 모델 후보 선정
- 기본 모델 → 프롬프트 개선 → LoRA/QLoRA 결과를 동일 평가셋에서 비교
- 문항별 점수, 근거 인용, 판단 보류, JSON 형식 준수를 함께 학습·평가
- 모델·데이터·루브릭·실험 설정을 버전으로 관리

완료 기준: 채점 기준 일치도와 인용의 충실도를 유지하면서 API와 비교할 수 있는 모델 확보. 모델 계열과 크기는 실험 당시 사용 가능한 후보를 검토해 결정.

## 4. 추론 서버와 비용 비교

- vLLM 등의 자체 서빙 구성과 서비스 API 어댑터 실험
- 동일한 출력 형식, 응답 검증, 평가 기준 유지
- 입력 길이와 동시 요청 수별 부하 실험
- 워밍업, 배치, 정밀도, 양자화, KV 캐시 설정의 영향 비교
- 병목이 확인되면 CUDA/Triton 최적화 실험
- 자체 모델 실패 시 API로 되돌리는 운영 방식 검토

완료 기준: 품질·지연 시간·총 운영비를 함께 비교한 결과로 전환 여부 결정. API가 유리한 구간은 유지.

## 측정할 지표

| 영역 | 지표 |
| --- | --- |
| 채점 | 문항 점수 MAE, 축별 일치도, 판단 보류의 적절성 |
| 근거 | 원문 인용 유효율, 인용이 해석을 뒷받침하는지에 대한 독립 검토 |
| 안정성 | JSON 형식 준수율, 실패·타임아웃 비율, 동일 답변 반복 채점 변동 |
| 성능 | 요청 전체 P50/P95 지연, 처리량, 동시 요청별 오류율 |
| 비용 | 성공한 검사 1건당 비용, 월간 예상 비용, API 대체 호출 비용 |
| GPU | 메모리 사용량, 이용률, 유휴 시간·시작 비용 포함 운영비 |

초기 MVP는 완성된 JSON을 한 번에 반환하므로 사용자 경험 지표는 요청 전체 지연을 우선합니다. TTFT와 토큰 처리량은 향후 추론 서버 내부 측정에 활용합니다.

현재 측정 결과는 없습니다. 비용 절감률이나 정확도 목표를 실제 성과처럼 제시하지 않습니다.
